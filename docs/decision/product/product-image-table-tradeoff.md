# 도서 이미지 저장 구조 설계

## 1. 배경

도서 등록 기능을 구현하면서 도서 이미지를 어떤 방식으로 저장할지 고민했다.

## 2. 비교

### (1) Product 테이블에 이미지 경로 저장

#### 장점
- 구현이 단순하다.
- 조회 시 Product 테이블만 조회하면된다.

#### 단점
- 대표 이미지 1장만 저장하기 쉽다.
- 상세 이미지 여러 장을 저장하기 어렵다.
- 이미지 개수가 늘어날 경우 컬럼이 계속 증가할 수 있다.
- 이미지 관련 정보가 Product 테이블에 섞인다.


### (2) ProductImage 테이블 분리

#### 장점
- 도서 1개에 여러 이미지를 저장할 수 있다.
- 대표 이미지와 상세 이미지를 구분할 수 있다.
- 이미지 정렬 순서 관리 가능
- Product와 Image의 책임이 분리된다.

#### 단점
- 테이블 증가
- 도서 등록 시 Product 저장 후 ProductImage를 추가로 저장
- 조회 시 Join 또는 추가 조회가 필요해진다.


## 3. 선택

Product와 ProductImage를 분리하였다.

```text
Product 1 : N ProductImage
```

이미지 타입은 Enum으로 구분하였다.

```java
THUMBNAIL
DETAIL
```

---

## 4. 적용 결과

도서 등록 시 다음 순서로 저장한다.

```text
Product 저장
↓
생성된 productId 획득
↓
대표 이미지 저장
↓
상세 이미지 저장
```

---

## 5. 회고

도서 이미지는 대표 이미지 1장뿐 아니라 상세 이미지 여러 장이 필요할 수 있다.

따라서 Product 테이블에 이미지 컬럼을 두는 것보다 ProductImage로 분리하는것이 확장성과 유지보수성에서 좋다고 판단하였다.
