# 관리자 도서 목록 이미지 노출 방식 결정

## 상황

관리자 도서 목록 조회 화면을 구성하면서 목록 조회 시 도서 썸네일 이미지를 노출할지 고민하였다.

## 선택지

### 1. 목록에서 썸네일 노출

#### 장점
- 도서를 시각적으로 빠르게 구분할 수 있다.
- 사용자 쇼핑몰 화면과 비슷한 느낌을 줄 수 있다.

#### 단점
- 이미지 로딩 및 경로 처리까지 목록 조회 책임에 포함된다.
- product_image 조인이 필요해 목록 조회 쿼리가 무거워질 수 있다.


### 2. 목록에서는 기본 정보만 노출하고, 상세 조회 시 이미지 노출

#### 장점
- 목록 화면이 단순하고 가독성 향상
- 목록 조회 쿼리가 product + category 중심으로 가벼워진다.
- 이미지는 상세 조회의 책임으로 분리할 수 있다.
- 관리자 입장에서는 도서명, 저자, 출판사명, 가격, 재고, 상태 확인이 더 중요하다.

#### 단점
- 목록 화면에서는 도서를 시각적으로 구분하기 어렵다.
- 이미지 확인을 위해 상세 화면으로 이동해야 한다.


## 결정

관리자 도서 목록에서는 이미지를 제거하고, 도서 상세 조회 화면에서 대표이미지와 상세 이미지를 보여주기로 결정

## 이유

관리자 도서 목록의 핵심 목적은 도서 데이터를 빠르게 조회하고 상태를 관리하는 것이다.
따라서 이미지보다 제목, 저자, 출판사명, 가격 등의 정보가 더 중요하다.

이미지 정보는 상세 조회에서 확인하는 것이 책임 분리 측면에서도 더 적절하다고 판단했다.

## 결과

- 관리자 목록 조회 쿼리에서 product_image 조인을 제거
- 목록 DTO에서 thumbnail_path 필드를 제거할 수 있게 됬다.
- 목록 JSP에서 이미지 컬럼 제거
