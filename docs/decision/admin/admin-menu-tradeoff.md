# 관리자 메뉴 노출 정책 설계

## 1. 문제 상황

관리자 기능을 추가하면서 헤더의 "관리자 페이지" 메뉴를 어떤 사용자에게 노출해야 하는지에 대한 고민이 있었다.

초기 구조는 아래와 같다.

```text
비로그인
→ 관리자 페이지 노출

USER
→ 관리자 페이지 노출

ADMIN
→ 관리자 페이지 노출
```

하지만 일반 사용자에게 관리자 메뉴가 보이는 것은 UX 측면에서 적절하지 않다고 판단하였다.

---

## 2. 고려한 방식

### (1) 모든 사용자에게 노출

#### 장점
- 구현이 간단하다.
- 별도의 조건 처리가 필요하지 않다.

#### 단점
- 일반 사용자에게 불필요한 메뉴가 노출된다.
- UX가 좋지 않다.

---

### (2) ADMIN 권한 사용자에게만 노출

#### 장점
- 관리자 메뉴가 필요한 사용자에게만 노출된다.
- UI가 깔끔해진다.
- UX 향상

#### 단점
- 비로그인한 상태에서는 관리자 로그인 진입 경로가 사라진다.

---

### (3) 비로그인 + ADMIN 권한 사용자에게 노출

#### 장점
- 관리자는 쉽게 관리자 페이지에 접근이 가능
- 로그인한 일반 사용자에게는 메뉴가 노출되지 않는다.
- 관리자 로그인 진입 경로를 유지할 수 있다.

#### 단점
- 조건 분기 로직이 추가된다.

---

## 3. 최종 선택

비로그인 사용자와 ADMIN 권한 사용자에게만 관리자 메뉴를 노출하는 방식을 선택하였다.

```text
비로그인
→ 관리자 페이지 노출

USER
→ 관리자 페이지 숨김

ADMIN
→ 관리자 페이지 노출
```

---

## 5. 회고

UI에서 관리자 메뉴를 숨기더라도 보안이 되는 것은 아니다.

따라서 실제 접근 제어는 `AdminCheckInterceptor`를 통해 수행하고,

헤더 메뉴 노출 여부는 사용자 경험 개선 목적으로만 사용하였다.
